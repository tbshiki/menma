# menma で原稿を書く

> 文書種別: 利用者向けガイド（正典ではない）
> 記法の正典: [記法仕様](./spec-markdown.md)。食い違ったら記法仕様が正しい
> このファイルは **AI にそのまま渡して使える**ように書いてある（[12 章](#12-ai-に原稿を書かせるとき)）

menma は **Markdown ファイル 1 枚**をスライドにする。覚えることは 4 つだけ。

1. `---` の行でスライドが分かれる
2. ファイルの先頭に設定（Front Matter）を書ける
3. `@slide` でそのスライドの見せ方を決める
4. `@aside` / `@notes` で領域を分ける

これ以外は**素の Markdown**。見出し、箇条書き、コード、表、引用、リンク、画像はいつもどおり書ける。

## 0. まずこれをコピーする

```md
---
title: 発表タイトル
author: あなたの名前
---

@slide layout=cover

# 発表タイトル

サブタイトルや日付

---

# 話すこと

- 1 つ目
- 2 つ目
- 3 つ目

---

@slide layout=center

# 一番伝えたいこと

---

# まとめ

- 覚えて帰ってほしいこと
```

`.md` として保存し、menma の入口画面へドラッグするか「ファイルを開く」で選べば発表できる。

## 1. ファイルの決まり

| 項目 | 決まり |
| --- | --- |
| 拡張子 | `.md` / `.markdown` / `.txt` |
| 文字コード | UTF-8 |
| 1 ファイル | 1 つの発表（デッキ）。複数ファイルの結合はしない |
| 画像 | 原稿と**一緒に選ぶ**（[7 章](#7-画像)） |

原稿も画像もブラウザの中だけで扱い、どこにも送信しない。読み込んだ原稿はブラウザに保存され、次に開いたとき「前回の原稿を開く」で再開できる。

## 2. スライドを分ける — `---`

単独行の `---` がスライドの区切りになる。

```md
# 1 枚目

本文。

---

# 2 枚目

本文。
```

規則。

| 書き方 | どうなるか |
| --- | --- |
| `---` だけの行（`-` は 3 つ以上） | 区切りになる |
| 前の行が本文で、間に空行がない | **区切りにならない**（Markdown では前の行が見出しになる） |
| コードブロック（3 連のバッククォートや `~~~`）の中の `---` | 区切りにならない（コードのまま） |
| `***` / `___` | 区切りにならない（ただの水平線） |
| ファイル先頭の Front Matter を閉じる `---` | 区切りにならない |

**区切りの前後には空行を入れる。** これが一番よくある失敗で、空行がないと 2 枚に分かれず、前の行が大きな見出しに化ける。

中身が空のスライドは捨てられる。`---` を続けて書いても空白ページはできない。**わざと真っ白なページを出したいときは `@slide layout=blank` を書く。**

## 3. ファイル先頭の設定 — Front Matter

ファイルの**先頭**に限り、`---` で囲んだ設定を書ける。全部省略できる。

```md
---
title: menma のはなし
author: tbshiki
lang: ja
showPageNumber: true
---
```

| キー | 型 | 既定値 | 内容 |
| --- | --- | --- | --- |
| `title` | 文字列 | `menma` | ブラウザのタブに出る題名 |
| `author` | 文字列 | 空 | 作者名（画面には出ない） |
| `lang` | 文字列 | `ja` | ページの言語 |
| `theme` | 文字列 | `default` | テーマ。**いまは `default` のみ** |
| `aspectRatio` | 文字列 | `16/9` | 画面比。**いまは `16/9` のみ** |
| `showPageNumber` | 真偽値 | `true` | 左下のページ番号を出すか |
| `showControls` | 真偽値 | `true` | 右下の操作ボタンを出すか |
| `showProgress` | 真偽値 | `true` | 画面下端の進み具合のバーを出すか |
| `pageBackground` | 色 | テーマの色 | スライドの外側（16:9 の余白）の色 |
| `progressColor` | 色 | テーマの色 | 進み具合のバーの色 |
| `transition` | 文字列 | `none` | ページの切り替え効果。**いまは `none` のみ** |
| `externalLinksNewTab` | 真偽値 | `true` | 外部リンクを別タブで開くか |

書式の制約。**ここは普通の YAML より狭い。**

- 書けるのは `キー: 値` の 1 行だけ。**入れ子・配列・複数行文字列は使えない**（`tags: [a, b]` は不可）
- 真偽値は `true` / `false` のみ
- 色は CSS が分かる書き方をそのまま書く（`#101418`、`tomato`、`rgb(0 0 0)`）
- ` # ` から行末はコメント。`#` の前後が空白のときだけコメントになるので、`title: C# 入門` や `pageBackground: #101418` は値の一部として扱われる
- 知らないキー・型の合わない値は**無視されるか既定値に戻る**。エラーで止まりはしない
- 閉じる `---` を書き忘れるとエラーになる

入口画面で余白とバーの色を設定した場合は、そちらが原稿の指定より優先される（「原稿の指定に戻す」で戻せる）。

## 4. 見せ方を決める — `@slide`

スライドの**最初の行**に書くと、そのスライドの見せ方を指定できる。

```md
@slide layout=center

# 大事なこと

これだけ覚えてください。
```

| 属性 | 値 | 内容 |
| --- | --- | --- |
| `layout` | 下表のレイアウト名 | 配置。未知の名前は `default` になる |
| `class` | 英数字・`-`・`_` | スライドに付ける自前のクラス（`mn-` で始まる名前は不可） |
| `background` | 画像のパス | 全面の背景画像。`cover` 向け |
| `backgroundColor` | CSS の色 | そのスライドの背景色 |
| `foreground` | CSS の色 | そのスライドの文字色 |

**この 5 つ以外は書けない。** 任意の HTML 属性やスタイルは指定できない。

### レイアウト

| `layout` | 見え方 | 使いどころ |
| --- | --- | --- |
| `default` | 左寄せの本文（省略時はこれ） | ふつうのページ |
| `center` | 上下左右の中央寄せ | 1 枚 1 メッセージ、章の区切り |
| `cover` | 表紙。`background` があれば全面に画像 | 1 枚目 |
| `split` | 左右 2 分割（`@aside` が右） | 本文と図を並べる |
| `image-left` | `@aside` が左、本文が右 | 図を先に見せたいとき |
| `image-right` | 本文が左、`@aside` が右 | 本文を先に読ませたいとき |
| `quote` | 引用を大きく中央に | 引用・キーメッセージ |
| `blank` | 何も装飾しない下地だけ | 余白のページ、自前で組むとき |

書式のこまかい点。

- 値に空白を含むときは `"` で囲む（例: `class="wide dark"`）
- 書けるのは**そのスライドの最初の非空行に 1 行だけ**。2 つ目以降や途中の `@slide` は本文として表示される
- `@slide` の次は空行を入れる

## 5. 左右に分ける — `@aside`

単独行の `@aside` から後ろが補助側の領域になる。

```md
@slide layout=split

# 仕組み

Markdown を読んで HTML にし、16:9 の枠へ収めている。

@aside

![流れ図](./diagram.svg)
```

- 1 スライドに 1 回だけ。2 回目以降は本文として表示される
- 2 領域を使わないレイアウト（`default` など）で書いた場合、補助側は本文の後ろに続けて表示される（内容は消えない）
- `split` / `image-left` / `image-right` は左右それぞれが独立して縦スクロールする

## 6. 発表者ノート — `@notes`

単独行の `@notes` から、そのスライドの終わりまでがノートになる。

```md
# 導入

- 背景
- 課題

@notes

ここは 2 分。会場の反応を見てから次へ。
```

- **いまは画面にも出力にも出ない。** 将来の発表者モードのために原稿へ残しておける
- `@aside` と一緒に使うときは `@notes` を必ず最後に置く

## 7. 画像

書き方は普通の Markdown。

```md
![流れ図](./images/diagram.png)
```

- **原稿と画像を一緒に選ぶ**（入口画面でまとめて選択、またはまとめてドロップ）。結び付けは**ファイル名だけ**で行うので、`./images/a.png` も `../assets/a.png` も `a.png` として扱われる
- 同じ名前の別画像を同時に使う原稿は正しく解決できない。**ファイル名は原稿の中で一意にする**
- 使える拡張子: `.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.avif` / `.svg`
- 大きさの上限: 1 枚 10MB、合計 50MB
- `https://` で始まる URL はそのまま読み込む（選ぶ必要はない）
- 画像は領域に収まるように縮小される
- 背景いっぱいに敷きたいときは `@slide layout=cover background=./cover.jpg`

## 8. 素の Markdown で書けるもの

見出し、箇条書き、番号付きリスト、**強調**、`インラインコード`、コードブロック（言語指定つき）、表、引用、リンク、画像、水平線（`***`）。

- 外部リンクは既定で別タブで開く（`rel="noopener noreferrer"` が付く）
- コードブロックは言語名を書いてよいが、色分けは今のところ無い
- 改行だけでは改行にならない（Markdown どおり。段落を分けるには空行）

## 9. できないこと・つまずくところ

| やりがちなこと | 実際の挙動 |
| --- | --- |
| `<br>` や `<div class="...">` などの HTML を書く | **効かない。** そのまま文字として表示される |
| `<style>` や CSS の直書きで装飾する | 効かない。見た目は `@slide` の 5 属性と `class` の範囲で調整する |
| `@slide` 以外の `@xxx` を書く | ただの本文として表示される |
| 1 枚に文章を詰め込む | **はみ出した分は切れる**（縮小されない） |
| `---` の前に空行を入れない | 区切られず、前の行が見出しに化ける |
| Front Matter に配列や入れ子を書く | 読めずに無視される |
| `theme` に `default` 以外を書く | `default` に戻る |

**1 枚の目安**: 見出し 1 つ + 箇条書き 6 行程度。本文は全角 40 字 × 10 行前後で画面が埋まる。迷ったらスライドを増やす。

`@slide` などを文字として見せたいときは、コードブロックに入れるか行頭に `\` を置く（`\@slide`）。

## 10. 発表する

| 操作 | キー |
| --- | --- |
| 次へ | `→` `↓` `PageDown` `Space` |
| 前へ | `←` `↑` `PageUp` `Shift+Space` |
| 最初 / 最後 | `Home` / `End` |
| 全画面 | `F` |

- URL の `#/3` で 3 枚目を直接開ける。ブラウザの戻る／進むも使える
- 左下のページ番号に**ポインタを 1.5 秒乗せる**か**ダブルクリック**すると「原稿を選ぶ」に変わり、そこを押すと入口画面へ戻る（発表中の誤クリックで飛ばないようにしてある）

### PDF にする

`Ctrl+P`（Mac は `Cmd+P`）で印刷ダイアログを開き、送信先に「PDF に保存」を選ぶ。**1 ページ 1 スライド**で、操作 UI や進み具合のバーが入らない PDF になる。

- 用紙は自動でスライドと同じ 16:9 になる。設定を変える必要はない
- 文字は画像ではなくテキストのまま入るので、検索・コピーができる。リンクも生きている
- 背景色や背景画像もそのまま出る（ブラウザの「背景のグラフィック」設定に関係なく出るようにしてある）
- `@notes` の内容は PDF にも出ない
- 紙に印刷するときは、ブラウザ側で用紙サイズに合わせて縮小される

## 11. 書き上がったらの確認

- [ ] 1 行目から書き始めた Front Matter を `---` で閉じたか
- [ ] すべての `---` の前後に空行があるか
- [ ] `@slide` はスライドの先頭行にあるか
- [ ] `layout` の名前は 8 種類のどれかか
- [ ] 画像のファイル名は重複していないか。原稿と一緒に選んだか
- [ ] 一番長いスライドが画面から切れていないか
- [ ] 表紙（`cover`）と締めのスライドがあるか

## 12. AI に原稿を書かせるとき

**このファイルをまるごと渡すのが確実。** 「このガイドの記法だけを使って、○○についてのスライドを書いて」と頼めばよい。

短く渡したいときは、次のブロックだけを貼っても足りる。

````text
menma 用の Markdown スライド原稿を書いてください。次の記法だけを使い、これ以外の構文は使わないでください。

# 全体
- 出力は Markdown ファイル 1 枚。前置きや解説を付けず、原稿だけを出す
- スライドの区切りは単独行の `---`。区切りの前後には必ず空行を入れる
- 中身が空のスライドは作らない

# 先頭の設定（任意・ファイル先頭のみ）
---
title: 題名
author: 名前
lang: ja
showPageNumber: true
---
- 書けるのは「キー: 値」の 1 行だけ。配列・入れ子・複数行は不可
- 使えるキー: title, author, lang, theme(default のみ), aspectRatio(16/9 のみ),
  showPageNumber, showControls, showProgress, pageBackground, progressColor,
  transition(none のみ), externalLinksNewTab
- 真偽値は true / false のみ

# スライドの指定（任意・そのスライドの最初の行に 1 行だけ）
@slide layout=center
- 使える属性は layout / class / background / backgroundColor / foreground の 5 つだけ
- layout に使える値: default, center, cover, split, image-left, image-right, quote, blank
- @slide の次の行は空行にする

# 領域の分割
- 単独行の @aside から後ろが補助領域。1 スライドに 1 回まで。split / image-left / image-right と一緒に使う
- 単独行の @notes から後ろが発表者ノート。画面には出ない。スライドの最後に置く

# 本文
- 素の Markdown（見出し・箇条書き・表・引用・コードブロック・リンク・画像）を使う
- HTML タグは使わない（無効で、そのまま文字として表示される）
- CSS やスタイル指定は書かない
- 画像は ![説明](./ファイル名.png) の形で書き、ファイル名は原稿全体で一意にする

# 分量
- 1 枚は見出し 1 つ + 箇条書き 6 行程度まで。本文は全角 40 字 × 10 行で画面が埋まる
- はみ出した分は表示されないので、詰め込まずスライドを増やす

# 構成
- 1 枚目は @slide layout=cover の表紙
- 強調したい 1 メッセージのページは @slide layout=center
- 図や画像と本文を並べるときは @slide layout=split（本文 → @aside → 画像）
````

AI が書いた原稿でよく直すことになる点。

- `<br>` や `<div>` で改行・段組みしようとする → 使えない。スライドを分けるか `@aside` を使う
- `two-column` や `title-slide` のような**存在しない layout 名**を作る → 8 種類のどれかへ直す
- Front Matter に `tags:` や `date:` など未対応のキーを書く → 無視されるだけなので消してよい
- 1 枚に説明文を詰め込む → 切れるので分割する
- 画像のパスを `./images/...` と書く → パスは自由だが、**その画像ファイルを原稿と一緒に選ぶ**必要がある
