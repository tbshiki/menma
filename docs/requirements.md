# menma 要件定義

> 文書種別: 要件定義（正典）
> 対象バージョン: MVP（v1.0）
> 関連: [記法仕様](./spec-markdown.md) / [設計](./architecture.md) / [ロードマップ](./roadmap.md) / [決定記録](./decisions.md)

## 1. プロダクト定義

**menma** は、Markdown ファイルを書くだけでブラウザからそのまま発表できる、軽量な Web スライドシステムである。

GUI 型のプレゼンテーションツール（PowerPoint / Google Slides / Keynote）の置き換えではなく、次の価値を優先する。

- 原稿を Markdown で書き、Git で履歴管理・レビューできる
- 静的サイトとして公開でき、その URL のまま登壇できる
- キーボードだけで発表できる
- 依存を少なく保ち、HTML / CSS の知識だけでデザインを拡張できる
- SaaS や外部サービスに依存しない
- AI に Markdown を書かせやすい（独自記法を増やしすぎない）

一言でいうと、**Markdown とブラウザの間に必要最小限のプレゼンテーション層を置く**プロジェクトである。多機能なスライドフレームワークを作ることは目的ではない。

## 2. 独立実装の原則（最重要制約）

menma は既存の Web スライドツールの複製ではなく、**同じ問題に対する別実装**である。

### 2.1 採用してよい一般的なアイデア

Markdown → HTML 変換、`---` によるスライド分割、左右キーでのページ移動、Space で次へ、全画面表示、URL から特定ページを開く、16:9 基準の表示、CSS によるテーマ切り替え、コードブロック・画像・表・引用・リンクの表示。

### 2.2 menma として独自に設計するもの

独自記法、URL 形式、操作 UI、レイアウトシステム、CSS クラス名、DOM 構造、テーマ変数、トランジション、エラーメッセージ、README、サンプルスライド。

### 2.3 禁止事項

- 他のスライドツールのソースコード・CSS をコピーしない
- 特徴的な文言や UI をそのまま再現しない
- DOM 構造を意図的に同一にしない
- 他サイト固有の画像・フォントを無断利用しない

外部からコードや文言を持ち込む場合は、出所とライセンスを確認し、その旨を変更の報告に含める。

## 3. 想定ユーザーと利用シーン

| 区分 | 内容 |
| --- | --- |
| 主なユーザー | エンジニア、技術イベント登壇者、社内勉強会の発表者、Markdown と GitHub に慣れた人 |
| 利用シーン | Meetup / LT / コミュニティイベント / 社内勉強会 / ワークショップ / 技術説明 / 提案資料 / オンライン配信 |
| 発表環境 | 会場のプロジェクタ（16:9 想定）、自分の PC のブラウザ、画面共有 |
| 閲覧環境 | 発表後に共有された URL を PC・スマートフォンで閲覧 |

MVP ではスマートフォンは「閲覧できる」ことを目標とし、スマートフォンからの発表操作は対象外とする。

## 4. スコープ

### 4.1 MVP に含む

1 リポジトリ 1 デッキ（`slides.md`）で、実際の登壇に使えるところまで。詳細は 5 章の機能要件に定義する。

### 4.2 MVP に含まない（明示的に対象外）

WYSIWYG 編集、リアルタイム共同編集、クラウド保存、ユーザー認証、コメント、アニメーション編集 GUI、PowerPoint / Google Slides / Keynote の相互変換、動画編集、発表者間同期。

### 4.3 MVP 後に検討する（v1.1 以降）

シンタックスハイライト、発表者モード、一覧（Overview）表示、PDF 出力、複数デッキ、テーマ追加、スワイプ操作、Mermaid、数式、Visual Regression Test。優先度は [ロードマップ](./roadmap.md) の「MVP 後の候補」を参照。

## 5. 機能要件

各要件は ID を持つ。ロードマップのタスク、テスト、Pull Request はこの ID を参照する。

### 5.1 原稿の読み込みと解析

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-01 | リポジトリ直下の `slides.md` をビルド時に読み込む | 開発サーバで `slides.md` を保存すると画面へ反映される。ビルド時にファイルが無ければビルドが失敗する |
| FR-02 | 先頭の YAML Front Matter をデッキ設定として解析する | [記法仕様 3 章](./spec-markdown.md#3-front-matter) の全キーが既定値付きで解釈される。未知キーは無視して開発時のみ警告 |
| FR-03 | トップレベルの `---` でスライドを分割する | Front Matter 区切りとコードフェンス内の `---` は分割しない |
| FR-04 | 標準 Markdown をレンダリングする | 見出し・段落・リスト・強調・リンク・画像・引用・コードブロック・表が表示される |
| FR-05 | `@slide` ディレクティブでスライド単位の属性を指定できる | `layout` / `class` / `background` / `backgroundColor` / `foreground` のみ受け付け、それ以外は無視して開発時のみ警告 |
| FR-06 | `@aside` でスライド本文を主要部と補助部に分割できる | `split` / `image-left` / `image-right` レイアウトで 2 領域として描画される |
| FR-07 | `@notes` を発表者ノートとして解析し、内部モデルへ保持する | MVP では画面にも HTML 出力にも現れない（v1.1 の発表者モードで利用） |

### 5.2 レイアウトと表示

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-08 | `default` / `center` / `cover` / `split` / `image-left` / `image-right` / `quote` / `blank` の 8 レイアウトを提供する | 各レイアウトが [記法仕様 4 章](./spec-markdown.md#4-slide-ディレクティブ) の描画契約どおりに表示される。未知の layout は `default` へフォールバックし開発時のみ警告 |
| FR-09 | 16:9 を保ったまま表示領域へ収める | 縦か横のどちらかが画面いっぱいになり、はみ出さない。比率が違う分は余白になるが、余白は白でほとんど目立たない。リサイズで追従する（[D-11](./decisions.md)） |
| FR-10 | 画像を領域内へ収める | `max-width` / `max-height` / `object-fit: contain` により、はみ出しやレイアウト破壊が起きない |
| FR-11 | CSS Custom Properties によるデフォルトテーマを提供する | 色・フォント・サイズ・余白がテーマ変数で定義され、テーマ CSS が DOM 構造に依存しない |
| FR-12 | 印刷時に 1 ページ 1 スライドで出力する | ブラウザの印刷プレビューで全スライドが 1 枚ずつ、UI 非表示、16:9 を維持して並ぶ |

### 5.3 操作

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-13 | キーボードでページ移動できる | [8.1 のキー割り当て](#81-キーボード割り当て)どおりに動作する |
| FR-14 | 入力要素へフォーカス中はページ移動キーを無視する | `input` / `textarea` / `select` / `button` / `contenteditable` にフォーカスがあるとき移動しない |
| FR-15 | URL のハッシュで現在ページを表現し、直接開ける | `#/5` を開くと 5 ページ目が表示される。ページ移動でハッシュが更新され、ブラウザの戻る／進むが機能する |
| FR-16 | 不正・範囲外のハッシュを安全に正規化する | 数値として解釈できない値は 1 ページ目、範囲外の数値は最も近い端のページへ丸める（[D-03](./decisions.md)） |
| FR-17 | 全画面表示へ切り替えられる | `F` キーで Fullscreen API を呼び出す。API 非対応環境でも発表自体は継続できる |
| FR-18 | ページ番号と最小限の操作 UI を表示する | **画面**の左下にページ番号、右下に前後の移動と全画面のボタン。スライドの外側に置くため、背景の明るさに応じて読める文字色にする。Front Matter で非表示にできる。発表の邪魔にならないよう小さく低コントラストにし、操作が無い間は減光する |
| FR-35 | 進み具合を画面下端のバーで示す | 現在位置に応じて幅が変わる細いバーを最下部に置く。Front Matter の `showProgress` で消せる |
| FR-36 | デッキ全体の色を指定できる | 対象は `pageBackground`（スライドの外側）と `progressColor`（進み具合のバー）。**入口画面の UI と Front Matter の両方から指定でき、UI の指定が優先される**（FR-37） |
| FR-37 | 色の指定を入口画面から変えられる | 入口画面で色を選ぶとそのブラウザに保存され、以降どの原稿でも使われる。既定へ戻せる。**優先順位は UI の指定 → 原稿の指定 → テーマの値** |

### 5.4 品質・安全性

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-19 | Markdown 内の raw HTML を既定で無効にする | `<script>` などを書いても HTML として実行されない |
| FR-20 | 外部リンクを別タブで開き、適切な `rel` を付与する | 既定 `externalLinksNewTab: true`。`rel="noopener noreferrer"` が付く |
| FR-21 | 読み込み失敗・空デッキ・不正 Front Matter を専用画面で通知する | 開発時は原因と行番号、本番は利用者向けの簡潔な文言を表示する（[記法仕様 7 章](./spec-markdown.md#7-エラー時の挙動)） |
| FR-22 | 基本的なアクセシビリティを満たす | `lang` 指定、キーボード操作可能、画像 alt、フォーカス可視、ページ切り替えの読み上げ通知、`prefers-reduced-motion` 対応 |
| FR-23 | 開発時のみデバッグログを出す | 本番ビルドに不要な `console` 出力を残さない |

### 5.5 原稿の読み込み（v0.2.0 で追加）

リポジトリを触らなくても、手元の Markdown をその場でスライドにできるようにする。MVP の受け入れ条件（9 章）には含めないが、実装済みの機能として同じ品質基準で扱う。

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-24 | 原稿を選んでいないときは入口画面を表示する | ハッシュの無い `/` で、ファイル選択・貼り付け・サンプルの 3 つの入口が出る |
| FR-25 | ローカルの Markdown ファイルを読み込める | ファイル選択とドラッグ&ドロップの両方。`.md` / `.markdown` / `.txt` を受け付け、複数選ばれた場合は 1 つ目を使う |
| FR-26 | 貼り付けた Markdown をスライドにできる | 入口画面のテキストエリアへ貼り付けて実行すると、そのままスライドになる |
| FR-27 | 読み込んだ原稿を次回も開ける | ブラウザ内（`localStorage`）へ保存し、リロードしても同じ原稿・同じページから再開できる。入口画面から消せる |
| FR-28 | 入口画面とスライドを行き来できる | デッキを開くと履歴へ積まれ、ブラウザの戻るで入口へ戻れる |
| FR-29 | 読み込みに失敗したときに理由を伝える | 対応外の拡張子、空の原稿、解釈できない Front Matter を入口画面へ表示し、直前の状態を壊さない |

制約と扱い

- **原稿を URL へ載せない。** 共有リンクから任意の内容を表示できると、menma のドメインを騙りに使えるため（設計 12 章の方針を維持）
- **原稿はブラウザの外へ出さない。** 送信も収集も行わない
- テキストエリアは入力経路であって編集機能ではない。4.2 の「WYSIWYG 編集を含まない」は変わらない

### 5.6 画像の取り込み（v0.3.0 で追加）

原稿と一緒に画像を選べるようにして、相対パスで書かれた画像を表示できるようにする。

| ID | 要件 | 受け入れ基準 |
| --- | --- | --- |
| FR-30 | 原稿と画像をまとめて選べる | ファイル選択とドラッグ&ドロップで複数のファイルを受け取り、Markdown 1 つと画像 0 個以上に振り分ける |
| FR-31 | 相対パスの画像を取り込んだ画像で置き換える | `![](./img/a.png)` のような相対パスを**ファイル名で照合**して表示する。同名が複数あるときは最初の 1 つを使い、警告する |
| FR-32 | 取り込んだ画像も次回そのまま開ける | 原稿と画像を IndexedDB へ保存し、リロードしても画像ごと再開できる |
| FR-33 | 大きすぎる画像を受け付けない | 1 枚 10MB、合計 50MB を上限とし、超えた分は取り込まずどのファイルが入らなかったかを伝える |
| FR-34 | 解決できなかった画像を伝える | 原稿が参照しているのに選ばれていない画像を、入口画面で名前付きで知らせる |

制約と扱い

- 対応する形式は `png` / `jpeg` / `gif` / `webp` / `avif` / `svg`
- **画像はファイル名だけで照合する。** 選択したファイルからはフォルダ構造が得られないため、原稿の `./img/a.png` と `../assets/a.png` は同じ `a.png` として扱う
- 絶対 URL（`https://` など）の画像は従来どおりそのまま読み込む。取り込みの対象にしない
- 画像も**ブラウザの外へ出さない**。保存先はこのブラウザの IndexedDB だけ
- `@slide background=` の背景画像も同じ方法で解決する

## 6. 非機能要件

| ID | 区分 | 要件 | 確認方法 |
| --- | --- | --- | --- |
| NFR-01 | 依存 | MVP の実行時依存は Markdown パーサ 1 つに限る。UI フレームワークを導入しない | `package.json` の `dependencies` レビュー |
| NFR-02 | 性能 | 画像を除く初期 JS を gzip 40KB 未満に保つことを開発目標とする（要件ではなく目標値）。**M3 時点の実測は gzip 54KB で目標を超過**。大半が markdown-it で、削減は v1.1 の課題（[D-16](./decisions.md)） | ビルド出力サイズの確認 |
| NFR-03 | 可搬性 | 成果物は静的ファイルのみ。サーバサイド処理を必要としない | `dist/` を静的サーバへ置いて動作確認 |
| NFR-04 | 対応環境 | 最新の Chrome / Edge / Firefox / Safari で動作する。IE は対象外 | E2E は Chromium で実施し、他は手動確認 |
| NFR-05 | 保守性 | パース層と DOM 層を分離し、パース層は純粋関数として単体テストできる | 設計レビューと単体テストの存在 |
| NFR-06 | 後方互換 | 一度公開した独自記法は安易に変更しない。変更する場合は記法仕様の更新と移行手順をセットにする | 記法仕様の改訂履歴 |
| NFR-07 | 安全性 | raw HTML 無効、`innerHTML` へ渡すのは Markdown パーサの出力に限る、URL クエリから HTML を生成しない、CDN を使わない | 実装レビュー |
| NFR-08 | 可読性 | Markdown 原稿はレンダリングしなくても読める。独自記法を最小限にする | 記法仕様のレビュー |
| NFR-09 | 検証 | typecheck / lint / 単体テスト / ビルド / E2E を CI で実行する | CI の成功 |

## 7. 制約

- パッケージマネージャーは pnpm。他のロックファイルを作らない
- Node.js は開発・ビルド時のみ必要。実行環境には不要
- 開発・検証は Windows 前提（AI 基盤のスクリプトが PowerShell）
- 1 リポジトリ 1 デッキ。複数デッキは v1.2 以降

## 8. 操作仕様（確定）

### 8.1 キーボード割り当て

| キー | 動作 | MVP |
| --- | --- | --- |
| `ArrowRight` / `ArrowDown` / `PageDown` / `Space` | 次のスライドへ | ○ |
| `ArrowLeft` / `ArrowUp` / `PageUp` / `Shift + Space` | 前のスライドへ | ○ |
| `Home` | 最初のスライドへ | ○ |
| `End` | 最後のスライドへ | ○ |
| `F` | 全画面の切り替え | ○ |
| `O` | 一覧表示 | v1.1 |
| `?` | 操作ヘルプ | v1.1 |
| `P` | 発表者モード | v1.1 |

MVP ではクリックによるページ送りを実装しない。リンクの誤操作とコード選択を妨げないため。スワイプは v1.1 で追加する。

### 8.2 端での挙動

最初のスライドで「前へ」、最後のスライドで「次へ」を行っても何も起きない（ループしない）。

## 9. MVP 受け入れ条件

すべて満たした時点で v1.0 とする。括弧内は検証手段。

1. `slides.md` を編集すると開発サーバの画面へ反映される（手動 / FR-01）
2. `---` でスライドを分割できる（単体テスト / FR-03）
3. 見出し・段落・リスト・強調・リンク・画像・引用・コード・表が表示できる（サンプルデッキ目視 / FR-04）
4. `@slide` の 8 レイアウトが期待どおり描画される（サンプルデッキ目視 / FR-05, FR-08）
5. 左右キー・Space で移動でき、端でループしない（E2E / FR-13）
6. `#/N` で任意ページを直接開け、共有した URL が同じページを開く（E2E / FR-15）
7. 不正なハッシュでも壊れない（E2E / FR-16）
8. `F` キーで全画面へ移行できる（手動 / FR-17）
9. 16:9 を維持してウィンドウ内へ収まり、リサイズで破綻しない（E2E / FR-09）
10. 印刷プレビューが 1 ページ 1 スライドになる（手動 / FR-12）
11. 空デッキ・不正 Front Matter で専用エラー画面が出る（単体テスト + 手動 / FR-21）
12. `pnpm build` の成果物が静的ファイルだけで動作する（手動 / NFR-03）
13. typecheck / lint / 単体テスト / ビルド / E2E が CI で通る（CI / NFR-09）
14. README を読めば新しい資料を書き始められる（レビュー）

## 10. 未決事項

決めるまで実装を止める必要はないが、リリース前に確定する。詳細と現時点の推奨は [決定記録の「未決事項」](./decisions.md#未決事項)を参照。

- ライセンス（推奨: MIT）
- 公開デプロイ先（確定: Cloudflare Workers の静的アセット）
- npm パッケージとして公開するか（MVP では公開しない前提）
