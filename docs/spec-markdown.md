# menma 記法仕様

> 文書種別: 原稿記法の正典（利用者向け仕様）
> 対象バージョン: MVP（v1.0）
> 関連: [要件定義](./requirements.md) / [設計](./architecture.md) / [決定記録](./decisions.md)

この記法は**公開後に安易に変更しない**（NFR-06）。変更する場合は本書の改訂と移行手順をセットにする。

## 1. 基本方針

- 素の Markdown をそのまま書ける。独自記法は「Markdown だけでは表せないこと」に限る
- 独自記法は行頭の `@` から始まる**ディレクティブ**に統一する。属性を持つ HTML ライクな記法や、コメント偽装記法は採用しない
- 原稿はレンダリングしなくても読める。ディレクティブは 1 行で完結し、本文を囲まない

## 2. スライドの分割

トップレベルの `---` だけを行に書くとスライドの区切りになる。

```md
# Slide 1

Hello.

---

# Slide 2

Next slide.
```

分割の判定規則。

| ケース | 分割する |
| --- | --- |
| `-` が 3 つ以上だけの単独行（行頭のインデントは 3 まで、行末の空白は可） | する |
| ファイル先頭の Front Matter を閉じる `---` | しない |
| コードフェンス（``` / ~~~）の内側の `---` | しない |
| `***` や `___`（Markdown の水平線の別表記） | しない（水平線として描画） |
| 直前の行が非空でセットアップ見出し（`===` / `---` による見出し）になる場合 | しない（見出しとして扱う） |

区切りの前後の空行は残しても消してもよい。分割後、各スライドの先頭・末尾の空行は取り除く。

取り除いた結果、内容が空になったスライドは**捨てる**。`---` を続けて書いた場合や原稿の末尾に `---` を置いた場合に、意図しない空白ページが生まれるのを防ぐため。意図的に何も無いページを出したいときは `@slide layout=blank` を書く。

## 3. Front Matter

ファイルの先頭に限り、`---` で囲んだメタデータを書ける。

```md
---
title: My Presentation
author: Your Name
lang: ja
theme: default
showPageNumber: true
---

# My Presentation
```

### 3.1 対応キー

| キー | 型 | 既定値 | 内容 |
| --- | --- | --- | --- |
| `title` | string | `menma` | HTML の `<title>` |
| `author` | string | `""` | 作者名（メタ情報としてのみ利用） |
| `lang` | string | `ja` | `<html lang>` |
| `theme` | string | `default` | テーマ名。MVP は `default` のみ |
| `aspectRatio` | string | `16/9` | 基準比率。MVP は `16/9` のみ |
| `showPageNumber` | boolean | `true` | ページ番号の表示 |
| `showControls` | boolean | `true` | 操作 UI の表示 |
| `transition` | string | `none` | ページ遷移。MVP は `none` のみ |
| `externalLinksNewTab` | boolean | `true` | 外部リンクを別タブで開く |

### 3.2 書式の制約

MVP の Front Matter は**フラットな `key: value` のみ**を解釈する（[D-04](./decisions.md)）。

- ネスト、配列、複数行文字列、アンカー、コメント以外の YAML 機能は対象外
- 値の前後の空白は取り除く。`"` または `'` で囲んだ場合は囲みを外す
- boolean は `true` / `false`（大文字小文字を区別しない）のみ。それ以外は型エラー
- 取りうる値が決まっているキー（MVP では `aspectRatio` は `16/9`、`transition` は `none`）に他の値を書いた場合も型エラーとして扱い、既定値へフォールバックする
- `#` から行末まではコメント。ただし引用符の内側は対象外
- 未知のキーは無視し、開発時のみ警告を出す
- 型が合わない値は既定値へフォールバックし、開発時のみ警告を出す
- Front Matter を閉じる `---` が見つからない場合はエラー（FR-21）

## 4. `@slide` ディレクティブ

スライドの先頭行に置くと、そのスライドの表示属性を指定できる。

```md
@slide layout=center

# 大事なこと

これだけ覚えてください。
```

### 4.1 書式

```text
@slide <name>=<value> [<name>=<value> ...]
```

- スライドの**最初の非空行**にある場合のみディレクティブとして解釈する。それ以外の位置では本文として扱う
- 値に空白を含む場合は `"` で囲む
- 1 スライドにつき 1 行まで。2 行目以降の `@slide` は本文として扱い、開発時のみ警告を出す

### 4.2 受け付ける属性

| 属性 | 値 | 内容 |
| --- | --- | --- |
| `layout` | 4.3 のレイアウト名 | 描画レイアウト。未知の値は `default` へフォールバック |
| `class` | 識別子（空白区切りで複数可） | スライド要素へ追加するクラス。`[A-Za-z0-9_-]` のみ許可 |
| `background` | 画像パス | 背景画像。`cover` レイアウト向け |
| `backgroundColor` | CSS の色 | 背景色 |
| `foreground` | CSS の色 | 文字色 |

**この 5 つ以外は受け付けない。** 任意の HTML 属性やインラインスタイルを注入する方式は採用しない（NFR-07）。色の値は CSS Custom Property 経由で適用し、そのまま HTML 属性へは書き出さない。

### 4.3 レイアウトと描画契約

| レイアウト | 描画 |
| --- | --- |
| `default` | 標準の左寄せ本文。見出し + 本文 |
| `center` | 本文を上下左右中央寄せ。1 スライド 1 メッセージ向け |
| `cover` | 表紙。`background` があれば全面背景画像 + 前景テキスト |
| `split` | 主要部と `@aside` を左右 2 分割（既定 1:1） |
| `image-left` | `@aside` を左、本文を右 |
| `image-right` | 本文を左、`@aside` を右 |
| `quote` | 引用を主役にした大きめの組版 |
| `blank` | 余白と既定の装飾を持たない下地のみ |

## 5. `@aside`

スライド本文を主要部と補助部に分ける。

```md
@slide layout=split

# 左側の内容

通常の本文。

@aside

![サンプル](./assets/sample.jpg)
```

- 単独行の `@aside` 以降が補助部になる
- 1 スライドにつき 1 回まで。2 回目以降は本文として扱い、開発時のみ警告を出す
- 2 領域を使わないレイアウトで `@aside` を書いた場合、補助部は主要部の後ろへ続けて描画する（内容は失わない）

## 6. `@notes`（発表者ノート）

```md
# スライドタイトル

本文。

@notes

ここは発表者だけに見えるメモ。想定 2 分。
```

- 単独行の `@notes` 以降、そのスライドの終わりまでをノートとして扱う
- **MVP では画面にも HTML 出力にも現れない。** 内部モデルにのみ保持し、v1.1 の発表者モードで利用する
- `@aside` と併記した場合、`@notes` は常に最後に置く

## 7. エラー時の挙動

| 状況 | 開発時 | 本番 |
| --- | --- | --- |
| スライドが 0 枚 | エラー画面 + 理由 | エラー画面（利用者向け文言） |
| Front Matter が閉じていない | エラー画面 + 行番号 | エラー画面（利用者向け文言） |
| Front Matter の型不一致 | 警告 + 既定値へフォールバック | 既定値へフォールバック（無言） |
| 未知の Front Matter キー | 警告 + 無視 | 無視（無言） |
| 未知の `layout` | 警告 + `default` | `default`（無言） |
| 未知の `@slide` 属性 | 警告 + 無視 | 無視（無言） |
| 未知のディレクティブ（`@xxx`） | 警告 + 本文として描画 | 本文として描画 |

エラー画面の文言は menma 独自に設計する（要件定義 2.2）。

## 8. エスケープ

`@slide` などを本文として表示したい場合は、コードブロックに入れるか、行頭の `@` の前にバックスラッシュを置く。

````md
```text
@slide layout=center
```

\@slide はディレクティブです。
````

## 9. 画像とアセット

- 画像は通常の Markdown 記法 `![alt](./assets/image.jpg)` を使う
- 相対パスの基準は `slides.md` の位置。ビルド時に解決できないパスはビルドエラーとする
- 画像は領域内へ収まるように描画する（FR-10）
- 背景画像は `@slide background=...` で指定し、CSS の `background-image` として適用する

## 10. リンク

- 外部リンクは既定で別タブで開き、`rel="noopener noreferrer"` を付与する
- Front Matter の `externalLinksNewTab: false` で同一タブへ変更できる
- 同一ドメイン内リンクとページ内アンカーは対象外

## 11. raw HTML

Markdown 内の raw HTML は**既定で無効**（FR-19）。将来 `allowHtml` を用意する場合も、明示的なオプトインとし、既定値は変更しない。

## 12. サンプル原稿

実装確認と E2E のフィクスチャを兼ねる `slides.md` を用意する。網羅する要素は cover / default / center / split / コード / 表 / 引用 / 画像 / リンク / 発表者ノート。
